# Anti AI-Slop UI/UX Design System

> **Mission:** Ban the repetitive, generic, and uninspired design monoculture generated by default AI outputs. Enforce intentionality, functional hierarchy, accessibility, and platform-native craftsmanship.

---

## 1. The Prohibited "AI Slop" Hall of Shame

Whenever generating or revising an interface, **NEVER** include the following default AI clichés:

| Cliché ("AI Slop") | Why it Fails | What to Do Instead |
| :--- | :--- | :--- |
| **Purple/Indigo Neon Glows** | Overused in 95% of AI mockups. Adds visual noise without functional meaning. | Use deliberate, brand-specific or platform-native semantic accents (Emerald, Slate, Sky, Amber). |
| **Generic 3-Column Bento Cards** | Mindless layout filler. AI puts 3 identical rounded cards with generic icons everywhere. | Design asymmetric, content-driven layouts that reflect actual hierarchy and real user workflows. |
| **Glassmorphism Overdose** | Blurry translucent backgrounds with poor contrast and visual artifacting. | Use solid, high-contrast elevated surfaces with subtle 1px borders (`#27272A` / `#3F3F46`). |
| **Marketing Fluff Copy** | Headings like *"Supercharge your workflow with next-gen intelligence"* say nothing. | Write direct, human, task-focused copy: *"Tu equipo sigue trabajando aunque cierres tu dispositivo."* |
| **Flat Font Monoculture** | Applying Inter or Roboto uniformly with identical font sizes and weights. | Establish an intentional scale with strong weight contrast (e.g., Bold 16pt + Regular 9.5pt + SemiBold 8pt). |
| **Missing States** | Interfaces that only exist in a frozen "happy path" state. | Always design the 6 core states: **Default, Hover, Active/Pressed, Focus-Visible, Disabled, Loading/Empty**. |
| **Alien UI Conventions** | Building a web SaaS dashboard inside a native desktop app or vice-versa. | Respect the platform: Windows Fluent (Segoe UI, Mica, Zinc/Slate, System Tray) vs. macOS HIG vs. Web. |

## 2. The Core Tenets of High-Craft UI/UX

### Rule 1: Utility & Information Density Over Decoration
* Every element, icon, border, and pixel must earn its right to exist.
* If removing an element doesn't degrade user understanding or workflow speed, **remove it**.
* Prioritize immediate readability and actionable controls over decorative fluff.

### Rule 2: Platform Authenticity
* **Windows Desktop (WPF, WinForms, WinUI):**
  * Typography: `Segoe UI Variable` or `Segoe UI`.
  * Layout: Consistent 8px grid (8, 16, 24, 32, 48px).
  * Dark mode palette: Deep charcoal (`#121214`), cards (`#18181B` / `#242427`), subtle borders (`#3F3F46`).
  * System Tray & Taskbar etiquette: Minimized to tray on close, clear balloon tips, single-instance mutex.
* **Web & Modern Apps:**
  * Clean, legible system font stacks.
  * Native interactive HTML elements (`<button>`, `<dialog>`, semantic forms).
  * High-performance, low-latency micro-transitions (< 150ms). Never use sluggish `transition: all 0.5s`.

### Rule 3: Accessible, High-Contrast Typography & Color
* Text must pass **WCAG AA** contrast ratios as a bare minimum (4.5:1 for normal text, 3:1 for large text).
* Reserve bold accent colors (Emerald `#10B981`, Amber `#F59E0B`, Crimson `#EF4444`) strictly for interactive calls to action or critical status alerts.
* Subtitle and helper text should be readable gray (`#A1A1AA` or `#9CA3AF`), never invisible washed-out gray.

### Rule 4: Human-Centric Microcopy
* Speak directly to what the software is actually doing.
* Avoid passive, robotic phrases.
* Examples:
  * ❌ *"Process lifetime management daemon execution state active"*
  * ✅ *"Equipo siempre activo"*
  * ❌ *"Audio hardware endpoint mute toggle triggered"*
  * ✅ *"Audio silenciado al cerrar"*

## 3. The "Anti-Slop" Audit Checklist

Before considering any UI design complete, run this audit:

- [ ] **Contrast Check:** Is every piece of text readable from 2 feet away in both light and dark ambient lighting?
- [ ] **Jargon Check:** Did you eliminate engineering terms (DWM, DPMS, ACPI, ThreadExecutionState) from user-facing screens?
- [ ] **Tactile Check:** Do buttons have distinct pressed and disabled states?
- [ ] **Keyboard Navigation:** Can the entire view be navigated with Tab, Enter, and Esc without getting trapped in focus loops?
- [ ] **Hierarchy Check:** Is the single most important action immediately obvious without scanning?
- [ ] **Responsive Rhythm:** Are paddings balanced (e.g., card padding 16-24px, row spacing 8-12px) without awkward dead space?

---

## 4. Application to Desktop & Native Software

When building native utilities like **AwakeWin**:
1. Keep window sizes compact and purpose-driven (e.g., 480x640px dialog rather than a bloated fullscreen window).
2. Use dynamic footer pills that summarize live hardware states in plain text with semantic icons (⚡ Batería, 🔊 Sonido, 🟢 Activo).
3. Ensure all secondary modal dialogs (like custom timers) match the exact color theme, typography, and corner styling of the parent window.
